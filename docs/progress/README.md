# Weekly progress log

One folder per week. Each folder holds two files.

| File | Written | Purpose |
|---|---|---|
| `plan.md` | Monday, at the stand-up | What each member is doing this week and what closes it |
| `log.md` | Appended as work happens, closed Sunday | What actually happened, decisions taken, blockers hit |

## Why this exists

Two reasons, and the second one is worth marks.

**It keeps the work findable.** A long conversation or a chat history is a bad place to
look for what was decided in week two. A dated folder is not.

**It is evidence for CLO 4.** The midterm rubric assesses "Agile Progress and Sprint
Backlog: sprint tracking, task management, and team milestone execution". A set of weekly
plan and log files, written as the weeks happened, is exactly that evidence. It cannot be
produced convincingly the night before, so write it as you go.

## Conventions

- Folder names are `week-01`, `week-02`, and so on, zero padded.
- Every log entry is dated.
- A decision that changes an analysis choice does not live here. It gets its own numbered
  memo in `docs/decisions/` and the log links to it.
- Attach the Sunday project board screenshot to the week folder as `board.png`.

## Working alongside the assistant

Keep one long running conversation as the project backbone, because the reasoning behind
the design lives there. Start a separate conversation for each week's build work. At the
end of the week, paste the week's outcomes into `log.md` so the repository, not the chat,
is the record.
